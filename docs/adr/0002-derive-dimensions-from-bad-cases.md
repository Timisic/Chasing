# 从 bad case 归纳评测维度，而不是先定维度再找 case

评测维度不是先入为主设计出来的，而是从大量使用中收集 bad case，再从 bad case 中抽象归纳。这是因为：(1) 第一版维度一定是错的，关键能力是"发现错误并修正"而不是"一步到位"；(2) 面试时可以说"我没有预设什么是好问题，而是先用、先观察、再归纳"，方法论本身就是加分项；(3) Aha 项目已经验证过这条路径（must/nice/noise 标注 → trace 回放 → 归因 → 迭代），是经过检验的做法。

## Considered Options

- **先定维度再验证**：看起来更"专业"，但容易陷入"什么维度才对"的焦虑而迟迟无法动手。且维度来源缺乏实证支撑
- **先用再归纳**：需要接受"我还不知道答案"的不确定性，但产出的维度有真实 bad case 作为证据，面试叙事更有说服力
