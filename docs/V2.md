# Chasing V2 修复说明

本文件记录 2026-08-16 首次真实长会话复盘后，由用户明确要求实施的 V2 行为。它覆盖 `PRD.md` 中与 Batch Grilling、阶段可见性、结束验收和 Langfuse 可靠性冲突的 V1 决策；其余 V1 约束继续有效。

## 真实 Bad Case

- 内部状态已经从 onboarding 进入 questioning/ending，但 Pi 状态栏一直显示 onboarding。
- 20 个正式问题中 18 个被“第一个问号截断”逻辑删除背景、例子或回答坐标。
- onboarding 只确认目标与角色，没有形成对“已知、模糊、未知、误解”的掌握度地图。
- 通用 curl 被安全边界拦截后，模型仍从参数记忆构造了来源记录；手工 retrievalId 随后传错，最终没有问题显示来源。
- Langfuse 不在线时没有持久化重试；一次完整的 48 事件会话没有进入 Langfuse。
- 模型在最终复述仍有遗漏时主观宣布 mission 完成。

## V2 决策

### 阶段

Pi 状态栏必须随内部状态即时显示：目标澄清、掌握度探测、任务确认、全景构建、盲区深挖、理解验收、结束确认。

### Batch 掌握度探测

- Batch 只允许出现在 mission 确认前。
- 一轮询问当前所有相互独立、先决条件已满足的 frontier 问题。
- 知识探测不提供推荐答案；“不知道”是有效证据。
- 回答后保存 mastery map：`known | partial | unknown | misconception`。
- mission 确认后恢复每轮一个认知任务。

### 问题渲染

问题由独立字段组成：`context`、`terms`、`example`、`question`、`answerGuide`、`sources`。只有 `question` 字段限制为一个问句；多问句必须报错，不能静默截断。背景需要达到“用户无需猜术语即可理解问题”的最小充分程度。

### 来源

- 外部事实只通过 `chasing_fetch_sources` 获取。
- 工具必须真实抓取 HTTPS 页面后才记录来源，并拒绝本机/私网地址及不安全重定向。
- 问题按 URL 自动关联最近的真实 retrieval，不再要求模型手工传 retrievalId。
- 参数记忆不能伪装成已抓取来源。

### Mission coverage

- mission 确认后定义 3–8 个 coverage 项。
- 学习过程中记录 `covered`，最终 teach-back 或决策复述后记录 `verified`。
- 至少回答一轮 verification 问题且所有 coverage 均 verified，才允许建议结束。
- 结束时仍不生成新的会话总结；mastery map 与 coverage 是持续维护的结构化地图。

### Langfuse

- 本地 JSONL 始终先落盘。
- 待同步事件先进入持久化 outbox，网络同步在后台执行并有硬超时，不能阻塞 Pi 对话。
- Observation ID 由 session + sequence 确定，支持安全重放。
- `/chasing-sync` 可重放当前 session；恢复服务后的新事件会自动冲刷 outbox。
- Langfuse 属性至少包含 phase、stage、intervention、问题/上下文/回答/可见输出长度、来源数量、模型、token usage 和完整原始事件。

## 验收

- session-level acceptance 覆盖 Batch 诊断、mastery map、阶段状态、结构化问题、真实来源、coverage 验收和轻量结束。
- persistence adapter 覆盖 outbox、恢复补传、历史 replay 和挂起端点不阻塞本地记录。
- Langfuse adapter 覆盖确定性 ID 与可分析属性。
